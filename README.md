# Cloudweb

Монорепозиторий двух Twitch-проектов: ИИ-бот чата и система анти-спам
модерации. Движки остаются **двумя независимыми процессами** — это осознанное
архитектурное решение, а не недоделанная интеграция (см. ниже). Панель у них
общая, одна на оба, и окружение тоже одно.

```
apps/twitch-bots/   ИИ-бот: читает Twitch IRC, отвечает, голосовой ввод
apps/cigilbot/      Анти-спам модерация: детекторы, кластеризация, движок
apps/panel/         Веб-панель обоих продуктов (порт 8766), общий вход
docs/               Планы и архитектура
var/                Рабочее состояние: БД, логи, pid-файлы (вне git)
_archive/           Остатки старой per-channel модели (вне git)
```

`apps/` — только исходники, `var/` — только данные. Раньше БД, логи и
pid-файлы лежали прямо в корнях проектов вперемешку с кодом; из-за этого
путь «корень проекта» незаметно означал сразу и место кода, и место
конфига, и место БД — и разошлось это только когда панель переехала.

## Как связаны два проекта

Связь только через файл на диске — без HTTP в горячем пути и без общего
кода:

```
apps/twitch-bots/main.py                  apps/cigilbot/cigilbot/consumer.py
  читает Twitch IRC                         держит ModerationEngine
  пишет каждое сообщение   --mod_inbox-->   разбирает очередь, анализирует,
  в bot.db                                   пишет verdict в mod.<id>.db
  (никогда не ждёт ответа)
```

`mod_inbox` — таблица в `apps/twitch-bots/bot.db`, то есть в файле **чужого**
проекта. `main.py` пишет туда и продолжает читать чат, не дожидаясь ответа;
`consumer.py` открывает своё соединение к тому же файлу (WAL-режим делает это
безопасным) и поллит его в фоне. Если Cigilbot не запущен, сообщения просто
накапливаются в очереди — ничего не теряется и не падает.

Путь к соседу задаётся переменной `BOT_PROJECT_ROOT`; по умолчанию это
`apps/twitch-bots` рядом. Переопредели её, если проекты лежат не рядом.

## Что разделено, а что общее

Разделены **движки**, и только они:

- **Устойчивость.** Падение модерации не должно уносить с собой бота, который
  в этот момент говорит в чате, и наоборот. Граница проходит по процессам
  `main.py` и `consumer.py`, а очередь `mod_inbox` между ними даёт ещё и
  backpressure: если модерация встала, чат не ждёт.
- **Разные зависимости.** `twitch-bots` тянет `twitchio` и (опционально)
  `faster-whisper`/`numpy`/`sounddevice`; `cigilbot` — `lingua` и `PyYAML`.
  Голосовые пакеты вынесены в отдельный `requirements-voice.txt` (~600 МБ) и
  ставятся, только если `VOICE_ENABLED=true`.

Общее — **панель, окружение и конфиг**:

- **Одна панель на порту 8766**, два экрана: `/moderation` и `/bots`. Раньше
  их было две на 8765 и 8766, и вход приходилось проходить дважды — порт
  входит в origin, поэтому cookie одного процесса не видна другому даже на
  localhost. Разделение стоило двух логинов и ничего не давало взамен: оба
  экрана всё равно жили бы или падали вместе с одним uvicorn.
- **Один `.venv` в корне.** Панель импортирует и `bot.*`, и `cigilbot.*` —
  из двух раздельных окружений один процесс не собирается.
- **Один `.env` в корне.** До слияния в двух файлах лежали одни и те же
  `PANEL_TWITCH_*` ключи с разными значениями, потому что двум панелям
  нужны были разные redirect URI.

## Установка

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements-dev.txt   # включает requirements.txt
copy .env.example .env

# Только если нужен голосовой ввод (~600 МБ)
.\.venv\Scripts\pip install -r requirements-voice.txt
```

## Запуск

```powershell
# Панель (порт 8766) — оба экрана, и из неё же запускаются бот и консьюмеры
cd apps\panel
..\..\.venv\Scripts\python -m panel.server
```

Этого достаточно: внутри панели крутится supervisor, который сам поднимает
`consumer.py` по `desired_state` каждого канала и умеет стартовать `main.py`.
Вручную процессы нужны только для отладки:

```powershell
cd apps\twitch-bots
..\..\.venv\Scripts\python main.py                    # Twitch IRC
..\..\.venv\Scripts\python voice_main.py              # только при VOICE_ENABLED=true

cd ..\cigilbot
# по одному на канал, аргумент — broadcaster_id из registry.db, не login
..\..\.venv\Scripts\python -m cigilbot.consumer 168599565
```

## Состояние

Модерация работает в **SHADOW-режиме**: анализирует чат и пишет вердикты в
БД, но сама никого не банит и не таймаутит, пока владелец канала явно не
включит исполнение. Phase 1 закрыт и проверен на живых каналах
(`dobriy_yura`, `paverpapa`). Следующее по плану — Phase 2, Alerts.
