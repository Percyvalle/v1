# Cloudweb

Монорепозиторий двух Twitch-проектов: ИИ-бот чата и система анти-спам
модерации. Проекты живут в одном репозитории, но остаются **двумя
независимыми процессами с раздельными окружениями** — это осознанное
архитектурное решение, а не недоделанная интеграция (см. ниже).

```
apps/twitch-bots/   ИИ-бот: читает Twitch IRC, отвечает, голосовой ввод
apps/cigilbot/      Анти-спам модерация: детекторы, кластеризация, панель
docs/               Планы и архитектура
_archive/           Остатки старой per-channel модели (вне git)
```

## Как связаны два проекта

Связь только через файл на диске — без HTTP в горячем пути и без общего
кода:

```
apps/twitch-bots/main.py                  apps/cigilbot/cigilbot/consumer.py
  читает Twitch IRC                         держит ModerationEngine
  пишет каждое сообщение   --mod_inbox-->   разбирает очередь, анализирует,
  в bot.db                                   пишет verdict в mod.<id>.db
  (никогда не ждёт ответа)
```

`mod_inbox` — таблица в `apps/twitch-bots/bot.db`, то есть в файле **чужого**
проекта. `main.py` пишет туда и продолжает читать чат, не дожидаясь ответа;
`consumer.py` открывает своё соединение к тому же файлу (WAL-режим делает это
безопасным) и поллит его в фоне. Если Cigilbot не запущен, сообщения просто
накапливаются в очереди — ничего не теряется и не падает.

Путь к соседу задаётся переменной `BOT_PROJECT_ROOT`; по умолчанию это
`apps/twitch-bots` рядом. Переопредели её, если проекты лежат не рядом.

## Почему раздельные окружения и процессы

Одно общее `.venv` и один процесс связали бы то, что специально разведено:

- **Устойчивость.** Падение модерации не должно уносить с собой бота, который
  в этот момент говорит в чате, и наоборот.
- **Разные зависимости.** `twitch-bots` тянет `twitchio`, `faster-whisper`,
  `numpy`, `sounddevice` (~600 МБ с моделью распознавания); `cigilbot` —
  `lingua`, `PyYAML` и ничего от голоса.
- **Раздельные панели.** 8765 (боты) и 8766 (модерация) не вызывают друг
  друга по HTTP; панель 8766 управляет `main.py` напрямую через subprocess.

Объединение репозиториев ничего из этого не меняет — общими стали только
история изменений, документация и правила игнорирования файлов.

## Запуск

У каждого проекта своя установка и свои команды — см. README внутри:

- [apps/twitch-bots/README.md](apps/twitch-bots/README.md) — бот чата и голос
- [apps/cigilbot/README.md](apps/cigilbot/README.md) — модерация и панель

Коротко, для рабочего стрима нужны три процесса:

```powershell
# Панель модерации (порт 8766) — из неё же запускается и сам бот
cd apps\cigilbot
.\.venv\Scripts\python -m panel.moderation_server

# Обработчик очереди — по одному на канал, broadcaster_id из registry.db
.\.venv\Scripts\python -m cigilbot.consumer 168599565

# Панель управления ботами (порт 8765), если нужна
cd ..\twitch-bots
.\.venv\Scripts\python -m panel.server
```

## Состояние

Модерация работает в **SHADOW-режиме**: анализирует чат и пишет вердикты в
БД, но сама никого не банит и не таймаутит, пока владелец канала явно не
включит исполнение. Phase 1 закрыт и проверен на живых каналах
(`dobriy_yura`, `paverpapa`). Следующее по плану — Phase 2, Alerts.
