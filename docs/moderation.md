# Cigilbot

Анти-спам модерация чата для Twitch. Отдельного процесса у неё нет —
движок работает внутри бота [`../twitch-bots`](../twitch-bots) (см.
[корневой README](../../README.md)). Разбирает каждое сообщение чата на признаки спама и
координированных атак (дубликаты, всплески сообщений, подозрительные
ссылки, невидимые символы, массовое появление новых аккаунтов) и
объясняет каждое решение конкретными наблюдениями — без "чёрного ящика".
Полная архитектура, инварианты безопасности и план развития — в
[`docs/moderation-plan.md`](../../docs/moderation-plan.md).

Работает в **SHADOW-режиме**: анализирует чат и пишет вердикты в БД — сам
по себе никого не банит и не таймаутит, пока владелец канала явно не
попросит реального исполнения через панель.

## Архитектура: библиотека внутри процесса бота

Cigilbot **не** подключается к Twitch IRC и не имеет своего процесса — чат
ему поставляет `../twitch-bots` (main.py), в котором движок и живёт:

```
twitch-bots/main.py                       cigilbot/pipeline.py (тот же процесс)
  читает Twitch IRC                         ModerationHub: движок на канал
  hub.submit(event)          --queue-->     разбирает в фоне, пишет verdict
  (возвращается сразу)                       в mod.<broadcaster_id>.db
```

Раньше здесь была граница процессов: main.py писал каждое сообщение в
таблицу `mod_inbox` на диске, а `consumer.py` — по процессу на канал, под
управлением supervisor'а — читал её в фоне. Теперь очередь в памяти.

Свойство, ради которого всё это строилось, сохранено: `submit()` не
корутина и ничего не ждёт, чтение чата не оплачивает запись в SQLite и
поход в Helix. Потеряно другое, и это осознанная цена: очередь не
переживает падение процесса и ограничена по размеру — при переполнении
события отбрасываются (со счётчиком и логом), потому что ждать значило бы
затормозить сам чат.

Состояние по-прежнему по файлу на канал: `mod.<broadcaster_id>.db` —
пользователи, кластеры, вердикты, паттерны, очередь действий
(BAN/TIMEOUT). Один общий движок на все каналы был бы не быстрее, а
неверен: `ModerationEngine` стейтфул (скользящее окно, кластеризация).

## Установка

Окружение и `.env` — общие на весь монорепо, ставятся один раз из корня:

```powershell
cd ..\..
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
```

Заполни корневой `.env`:
- `PANEL_TWITCH_CLIENT_ID` / `PANEL_TWITCH_CLIENT_SECRET` — отдельное
  Twitch-приложение для входа в панель (см. комментарии в `.env.example`)
- `PANEL_TWITCH_CHANNEL`, `PANEL_SESSION_SECRET`
- `TWITCH_MOD_*` — не трогать руками, заполняются кнопкой "Получить токен
  бота" в Settings панели
- `INTERNAL_SYNC_TOKEN` — нужен только внешнему вызову
  `POST /api/registry/channels`. Изнутри реестром никто по HTTP не ходит:
  он один на монорепо (`var/registry.db`), зеркалить нечего

Конфигурация каналов **не в `.env`**: источник правды — `var/registry.db`,
канал добавляется на экране `/bots` панели. Файлов `.env.<профиль>` здесь
нет — они остались от старой per-channel модели, убранной в Phase 1 (у
twitch-bots они, наоборот, живы).

## Запуск

```powershell
# Панель (порт 8766) — общая на оба проекта, живёт в apps/panel
cd ..\panel
..\..\.venv\Scripts\python -m panel.server
```

Отдельно запускать нечего: движок поднимается вместе с ботом (`main.py`),
на каждый канал с `desired_state=running` в Registry. Кнопки start/stop в
панели меняют это поле, а бот подхватывает изменение на следующем тике
сверки.

Панель откроется на `http://localhost:8766/`. Вход через Twitch:
владелец канала получает роль OWNER, модераторы канала — MODERATOR,
остальные — VIEWER; ADMIN назначается вручную существующим OWNER/ADMIN
через экран Panel Users.

**Реальные баны/таймауты** (кнопки BAN ALL/TIMEOUT ALL в панели) требуют
токен модератора со scope `moderator:manage:banned_users` — получается
прямо в браузере: Settings панели -> «Получить токен бота», войти на
Twitch ПОД АККАУНТОМ БОТА (не под личным), аккаунт бота должен быть
модератором канала (`/mod <бот>` в чате). Без него задания в очередь
принимаются, но не исполняются.

## Структура проекта

```
cigilbot/              — движок: детекторы, кластеризация, скоринг, policy
cigilbot/pipeline.py   — движок в процессе бота: очередь на канал, фоновые
                          задачи, исполнение очереди действий (BAN/TIMEOUT)
cigilbot/store.py      — персистентность (своя mod.<broadcaster_id>.db)
cigilbot/registry_store.py — Channel Registry (var/registry.db, один на монорепо)
config/moderation.yml  — веса и пороги детекторов
config/channels/       — профиль языка/настроек по конкретному каналу
scripts/replay.py      — прогнать историю чата (из twitch-bots) через движок
scripts/report.py      — сводка shadow-статистики и false positives
```

Панели здесь больше нет: она переехала в [`../panel`](../panel) и стала
общей на оба проекта. Вместе с ней уехали `panel/auth.py` (существовавший
в двух почти одинаковых копиях) и тесты панели.
