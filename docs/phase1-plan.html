CigilBot · TWITCH BOTS — Master Plan, направление 00

Phase 1 — Channel Registry и управляемые процессы

Миграция с ручной файловой модели (.env.<profile> на канал, запуск в терминале) на управляемую архитектуру: единый Channel Registry, один бот-аккаунт на все каналы, supervisor и полностью разделённые панели управления.

Проекты: TWITCH BOTS + Cigilbot Каналы: dobriy_yura, paverpapa Обновлено: 09.08.2026

Phase 1 завершён и проверен на живых каналах. Все 8 шагов исходного плана выполнены, прошло security/correctness-ревью, найденные баги исправлены.

01

Архитектурные решения

Ключевые повороты относительно первоначальной файловой модели.

Один бот-аккаунт на все каналы
Не нужно заводить отдельный Twitch-аккаунт под каждый канал — один процесс main.py слушает все каналы разом через initial_channels.
решено
Идентификация по broadcaster_id
Канал определяется стабильным числовым Twitch ID, не по login (никнейм можно сменить).
решено
Два независимых Channel Registry
Свой registry.db в каждом проекте — TWITCH BOTS источник правды, синхронизация через один internal-эндпоинт.
решено
Cigilbot — один consumer на канал
В отличие от бота, детектор остаётся per-channel процессом: ModerationEngine стейтфул, смешивать состояние каналов рискованно.
решено

03

Security-ревью и фиксы

По запросу «перепроверить всё, найти баги/эксплойты, оптимизировать» — весь новый код сессии проверен по трём направлениям: security, race conditions, производительность.

Утечка файловых дескрипторов
Popen открывал лог-файлы без закрытия в родителе — накапливалось при частых рестартах через supervisor.
critical → fixed
TOCTOU-гонка на pid-файлах
Двойной клик Start или гонка supervisor/ручного вызова могли породить два процесса на один канал.
medium → fixed
PID reuse false positive
tasklist проверял только число PID — Windows может переиспользовать его в окне тика supervisor'а.
medium → fixed
Расхождение источника токена
INTERNAL_SYNC_TOKEN читался по-разному в двух проектах — унифицирован приоритет env→файл.
medium → fixed
SQLite busy_timeout
Не был выставлен — конкурентная запись могла упасть мгновенно вместо ожидания.
medium → fixed
Мёртвый код bot_process
Таблица и методы от старого плана авто-restart удалены — риск оборвать модерацию на живом стриме.
low → removed
04

Разобранный инцидент дня

⚠ Статистика не собиралась во время живого стрима

Симптом: стрим идёт, чат активен, но панель не показывает никакой статистики или ленты сообщений.

Причина: .env.cigilbot содержал устаревшую настройку INSTANCE=cigilbot от старой per-channel модели. Из-за неё main.py писал сообщения в bot.cigilbot.db, а cigilbot/consumer.py жёстко читает общий bot.db — бот работал нормально и видел чат, но вся статистика утекала в файл, который никто не читал.

Фикс: INSTANCE убран из .env.cigilbot, main.py перезапущен — подтверждено на живых данных: сообщения пишутся в правильный файл, consumer детектирует кластеры и логирует решения в реальном времени.
