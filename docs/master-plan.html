CigilBot — Master Plan

От детектора спама на одном канале до операторской платформы модерации на десятках Twitch-каналов. Зафиксировано по итогам совместного проектирования; ничего из этого ещё не реализовано.

9 направлений 31 функция Реализовано: детекция + панель на 1 канал
Концепция

Что строим

CigilBot сегодня — процесс-детектор спама и ботов для одного Twitch-канала: читает чат через очередь, прогоняет через движок сигналов (9 детекторов + кластеризация), показывает рекомендации в панели, исполняет баны только по ручному подтверждению.

CigilBot, каким он должен стать — операторская платформа для одного человека (оператора), ведущего модерацию на десятках каналов чужих стримеров одновременно, где каждый стример при желании получает изолированный доступ только к своему каналу. Детекция уже сильная сторона системы; то, чего не хватает — способа управлять этим на масштабе, а не с одного канала за раз через терминал.

Три принципа, зафиксированных в ходе проектирования, действуют как ограничения на все решения ниже:

  • Ручное подтверждение — дефолт, не догма. Из коробки автоматизация допускается только для явных случаев на фиксированном очень высоком пороге, с окном отмены. Полная автоматизация — осознанный per-channel выбор, а не системное поведение по умолчанию (направление 07).
  • Каналы изолированы по умолчанию. Стример не видит и не знает о существовании других каналов на платформе.
  • Explainable прежде AI. Там, где обычная статистика/правило даёт нужный результат — используется оно, не модель.
Роли и доступ

Кто что видит

Модераторская панель закрыта для рядовых зрителей полностью — доступ только у тех, кто управляет каналом. Роль VIEWER здесь удалена: обычный зритель чата в эту панель не заходит никогда, ни при каких правах. Его путь — отдельный публичный сайт, см. направление 08.

Operator
Ты · глобальный

Единый вход, видит все подключённые каналы сразу, глобальные Alerts и Analytics across каналов. Новая роль, не существует в системе сегодня.

Channel Owner
Стример · свой канал

Видит и настраивает только свой канал. Не знает о существовании других каналов на платформе. Совпадает с текущим OWNER.

Moderator
Команда стримера · свой канал

Назначается Channel Owner’ом, действует в рамках одного канала. Без изменений от текущей модели.

Admin
Ручной оверрайд · свой канал

Существующая роль без изменений — ручное назначение прав сверх того, что даёт Twitch-статус модератора/владельца.

Роль VIEWER (read-only внутри модераторской панели) убрана из системы — заменена полным отсутствием доступа для не-модераторов.

Направление 00 · Фундамент

Multi-Channel Foundation

Разблокирует всё остальное. Без этого Analytics не может агрегировать across каналов, а Alerts не с чем связать. Согласовано как первый блок работы.

Channel Registry

CriticalHigh

Центральная таблица каналов (id, login, статус, дата подключения) вместо файлов .env.<profile>. Добавление канала — действие в UI, не DevOps-операция.

Модератор видит: экран Channels — список, статус live/offline/error, переключатель.

Роль Operator

CriticalMedium

Флаг is_operator поверх текущей per-channel ролевой модели. Даёт доступ к списку всех каналов и глобальным экранам, не заменяя изоляцию Channel Owner.

Управляемые consumer-процессы

CriticalMedium

Supervisor поднимает по одному consumer-воркеру на канал, перезапускает при падении, отражает статус в Channel Registry — вместо ручного запуска через терминал.

Модератор видит: статус «жив / упал / перезапускается» на экране Channels.

Согласовано как фундамент — делаем в числе первых
Направление 01

Alerts / Notifications

Оператор физически не может держать в фокусе десятки чатов одновременно — узнаёт об атаке через Discord, не через панель.

Discord-webhook на подтверждённый кластер

CriticalLow

Триггер — только на новый активный кластер, не на единичные вердикты (естественный фильтр от шума). Embed: канал, число ботов, топ-сигналы, ссылка.

Per-channel, без сводного канала оператора — webhook настраивается в Settings каждого канала отдельно; алерты одного канала не смешиваются с другими.

Deep-link в панель

CriticalLow

Ссылка вида /moderation?channel=X&cluster=Y — панель сразу открывает нужный канал и подсвечивает кластер, без ручного поиска.

Ежедневный digest

HighLow

Сводка активности + проверка, что все consumer-процессы живы. Ловит «тихо упавший процесс», который атака-алерт не поймает.

Эскалация при повторных атаках

MediumMedium

3+ кластера за короткое время на одном канале — сигнал, что базовая защита не справляется, алертится отдельно, громче обычного.

Направление 02

Analytics

Заявленный приоритет. Три разных вопроса, три разных отчёта — не один общий дашборд.

Moderation Effectiveness

CriticalMedium

Тренд по времени: кластеров/день, FP-rate по каждому сигналу, сравнение эффективности across каналов. Данные уже есть в mod_stats_daily/mod_feedback — не хватает визуализации.

Chat Health

HighMedium

Активность реальных зрителей: сообщений/минуту, уникальные чаттеры, retention между стримами, доля новых аккаунтов. То, ради чего стример вообще смотрит в панель помимо модерации.

Incident Timeline

HighHigh

Атака как единица данных со своей таймлайн: начало → пик → конец, состав участников, применённые действия. Новая сущность mod_incidents поверх существующих кластеров — не просто фильтр списка.

Retention Policy

CriticalMedium

Сырые сообщения хранятся 30 дней, дальше — только агрегаты. Вердикты/кластеры/действия остаются навсегда (доказательная база банов). Без этого Chat Health создаёт риск неограниченного роста базы.

Направление 03

Moderation

Усиление уже работающей системы, включая уникальное преимущество мульти-канальности.

Cross-Channel Bot Fingerprint

HighMedium

Аккаунт, забаненный на канале A, получает risk-boost при появлении на канале B. Общая таблица known bad actors across всех каналов оператора — то, что одиночный бот на одном канале не может себе позволить.

Raid Shield

HighLow

Авто-детект начала рейда (событие raid_started уже приходит в очередь) временно ужесточает пороги, аналогично ручному Attack Mode — но без необходимости включать его вручную на каждом из десятков каналов.

Прогрессивные таймауты

MediumLow

Длительность растёт при повторных нарушениях (prior_timeouts уже есть в данных, просто не используется для расчёта). Для пограничных случаев — токсичный человек, не бот.

Watchlist

MediumLow

Противоположность marked_safe: пользователь под наблюдением, ещё не заслуживший бан. Небольшой risk-boost на будущих сообщениях, отдельная вкладка.

Направление 04

User Intelligence

Risk Profile History

HighLow-Medium

Агрегированная карточка пользователя: таймлайн всех вердиктов/действий across каналов, не просто счётчики prior_timeouts/prior_warnings.

Trusted Regulars как вкладка

MediumLow

Делает TrustLevel.REGULAR видимой позитивной категорией, а не только тихой скидкой на risk_score.

Behavior Similarity Network

LowHigh

Embedding-поиск похожего поведения на ранее забаненных без явного совпадения текста. Плохо сочетается с принципом explainable — модератор не может проверить, почему сработало. Малый прирост ценности за большую сложность; оставлено как идея, не как план.

Направление 05

Stream Intelligence

Live Stream Session Marker

HighLow

Явная граница онлайн/офлайн через Twitch EventSub. Фундамент для честной Analytics по стримам, а не по календарным дням — без него Incident Timeline не может ответить «что было на этом стриме».

Post-Stream Report

MediumLow

Авто-сводка после каждого стрима: пойманные атаки, здоровье чата, сравнение с прошлыми стримами. Автоматизация того, что уже делалось вручную.

Unusual Activity Detection

MediumMedium

Статистическая аномалия (отклонение от исторического бейзлайна канала), не LLM. Флаг «необычная активность» без интерпретации причины — модератор решает, рейд это или хайп.

Направление 06

Dashboard / UX

Operator Home → Channel Workspace

CriticalMedium

Стартовый экран «All Channels» (статус, последний алерт, мини-метрики) для Operator; клик на канал открывает существующий интерфейс в контексте одного канала. Channel Owner попадает сразу в свой Workspace, экран All Channels ему не показывается.

Реорганизация вкладок

HighMedium

Группировка растущего списка вкладок: Live · Analytics (Effectiveness + Chat Health + Incidents) · Users (+ Risk Profile + Watchlist) · Automation (Patterns + Attack/Giveaway/Raid Shield) · Settings · Audit.

Global Alerts Feed

MediumLow

Та же лента, что уходит в Discord, дублируется внутри Operator Home с deep-link — не нужно проверять Discord отдельно, если ты уже в панели.

Направление 07

Automation

Из коробки — ограниченное отступление от ручного подтверждения только для явных случаев. Отдельно — переключатель, дающий каналу выбрать более широкую автоматизацию осознанно.

Moderation Mode: Manual / Automatic

БудущееHigh

Переключатель на уровне канала (Settings), не глобальный. Manual (дефолт) — сегодняшнее поведение: рекомендации ждут подтверждения, автобан работает только на узком фиксированном пороге. Automatic — движок сам исполняет TIMEOUT/BAN по обычным risk_thresholds, без ограничения «только явные случаи».

Каждый канал решает сам, доверяет ли он автоматизации — стример с активным сообществом модераторов может остаться на Manual, канал без своей команды модерации может включить Automatic.

Autoban на фиксированном пороге

HighMedium

Жёсткий порог (например risk≥95, confidence≥0.95, ≥3 независимых семейств) — простой, предсказуемый, без per-channel настройки. При срабатывании — короткое окно отмены перед реальным исполнением в Helix, не тихий бан.

Отмена — через deep-link в панель из Discord-алерта, без живой кнопки в самом Discord (см. правило ниже). Окно должно быть достаточно длинным, чтобы дойти до панели и успеть отменить.

UNBAN

HighLow

Отсутствует в текущем executor.py (только BAN/TIMEOUT/DELETE_MESSAGES). Обязателен как парная функция к autoban — без него исправление ошибочного бана требует выхода на сам Twitch.

Направление 08 · Отложено на будущее

Public Site & Viewer Identity

Осознанно вынесено за пределы ближайших фаз — обсуждено, чтобы не проектировать модераторскую панель так, что потом придётся переделывать. Полностью отдельная поверхность от Channel Workspace: свой домен, свой доступ, свои данные.

Публичный лендинг (cigilbot.com)

БудущееMedium

Анонимный посетитель видит презентацию продукта и инструкцию подключения бота к своему Twitch-каналу. Не требует авторизации.

Вход стримера → его Channel Workspace

БудущееLow

Тот же Channel Workspace, что и в направлении 06, только точка входа — публичный домен вместо прямой ссылки от оператора. Self-serve вместо ручного подключения.

Личный кабинет зрителя

БудущееMedium

Обычный зритель (не стример, не модератор) авторизуется через Twitch и видит свою личную статистику по каналам, где подключён CigilBot — например, статус Trusted Regular, на каких каналах он известен боту. Полностью изолировано от модераторских данных — не расширение роли VIEWER, а отдельная сущность без доступа к панели модерации.

Направление 09 · Отложено на будущее

Discord Live Actions

Правило по умолчанию: Discord-алерты — только чтение и deep-link в панель, без живых действий внутри самого Discord. Живое действие требует отдельного продумывания (подтверждение личности нажавшего, гонки между несколькими модераторами, аудит) — осознанно вынесено за пределы ближайших фаз, включая тот случай (отмена autoban), где раньше рассматривалось как обязательное исключение.

Discord-кнопка отмены autoban

БудущееLow

Живое действие прямо в Discord-алерте для отмены autoban на явных случаях. Пока — отменяется только через deep-link в панель (см. направление 07).

Discord-кнопка BAN ALL на кластер

БудущееMedium

Мгновенное действие на подтверждённый кластер прямо из алерта, без перехода в панель. Ранее уже откладывалось отдельно («интересно, но не сейчас») — здесь для полноты как часть одного общего принципа.

Roadmap

Фазы реализации

Порядок определяется зависимостями, не только приоритетом — Phase 1 разблокирует всё, что после неё ссылается на каналы/статусы/токены по-канально.

ФазаФокусВключаетПочему в этом порядке
Phase 1 Core Channel Registry · роль Operator · управляемые consumer-процессы Блокер для всего остального — Analytics и Alerts не с чем связать без единой модели каналов.
Phase 2 Alerts & Visibility Discord-webhook на кластер · deep-link · digest · Operator Home Даёт немедленную операционную ценность на масштабе — оператор перестаёт зависеть от ручного мониторинга.
Phase 3 Moderation Raid Shield · Cross-Channel Fingerprint · Watchlist · прогрессивные таймауты Усиливает уже сильную часть системы, использует данные, которые Phase 1 сделала общими across каналов.
Phase 4 Analytics Retention Policy · Moderation Effectiveness · Chat Health · Stream Session Marker Retention — предпосылка для Chat Health; Session Marker нужен, чтобы отчёты не путали дни со стримами.
Phase 5 Intelligence Incident Timeline · Risk Profile History · Post-Stream Report · Unusual Activity Detection Требует накопленных агрегатов из Phase 4 — новые сущности строятся поверх уже устоявшихся данных.
Phase 6 Automation Autoban с окном отмены (deep-link) · UNBAN Наиболее рискованная категория изменений — заводится последней, когда детекция и мониторинг уже проверены на масштабе. Moderation Mode (Manual/Automatic) — отдельно, после того как autoban на явных случаях накопит доверие на практике.
Phase 7 Polish Реорганизация вкладок · Trusted Regulars · Global Alerts Feed · эскалация при повторных атаках UX-доводка после того, как функциональная поверхность устоялась — реорганизовывать вкладки раньше означало бы делать это дважды.
Phase 8 Public Site Лендинг · self-serve вход стримера · личный кабинет зрителя Осознанно отложено — не блокирует ничего выше, требует отдельного домена и публичного слоя доступа, который сегодня не существует.
Phase 9 Discord Live Actions Кнопка отмены autoban · BAN ALL из алерта Осознанно отложено — deep-link в панель уже покрывает эти сценарии сегодня; живые действия в Discord требуют отдельного решения по аутентификации нажатия и аудиту.
Зафиксированные решения

Открытые вопросы, закрытые в ходе проектирования

Кто видит что на десятках каналов?
Operator видит всё с одного входа. Channel Owner/Moderator видят и управляют только своим каналом, не зная о существовании других.
Есть ли у обычных зрителей доступ к модераторской панели?
Нет, никогда — роль VIEWER удалена из панели. Зритель получает свой собственный вид только в будущем публичном сайте (направление 08): личную статистику по каналам, где стоит бот, без доступа к данным модерации.
Автоматизация или ручное подтверждение?
Ручное — дефолт из коробки. Автобан на фиксированном очень высоком пороге с окном отмены работает всегда. Дополнительно — per-channel переключатель Manual/Automatic (направление 07): канал может осознанно перейти на полную автоматизацию TIMEOUT/BAN по обычным порогам, если доверяет системе.
Как оператор узнаёт об атаке, не глядя в панель?
Discord, per-channel (не сводный канал оператора) — алерт только на подтверждённый кластер, не на единичные вердикты.
Сколько хранить сырые сообщения чата?
30 дней, дальше только агрегаты для Analytics. Вердикты/кластеры/действия — бессрочно, как доказательная база.
Нужны ли Discord action-кнопки?
Нет, без исключений — включая отмену autoban. Все Discord-алерты остаются read-only с deep-link в панель; живые действия в Discord (включая кнопку отмены autoban) осознанно отложены в направление 09.
