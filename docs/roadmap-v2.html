Что уже держит вес

Прежде чем добавлять новые направления — то, на чём они будут стоять, проверено по реальному коду, не по памяти.

Команды чата

Poll-снапшот раз в 2 сек из SQLite, не push-по-событию. Годится для новых метрик, не годится для OBS-команд с низкой задержкой.

Решено 13.08.2026

Основа — делаем сейчас, без отклада

Всё остальное в этом документе (57 идей суммарно) осознанно отложено в банк — не потеряно, но и не в ближайшей работе. Порядок карточек ниже — реальный порядок работы, решённый в аудите 13.08: начинаем с самого дешёвого и видимого, не по номеру фазы.

1. Trusted Users экранНачинаем отсюда
TrustLevel и mod_trusted уже существуют и уже используются движком — не хватает только экрана в панели. Самый дешёвый пункт из всех 57 идей в документе, первый видимый результат.
2. Добить Moderation (Фаза 3)Основа
Watchlist, Warning System, Review Queue — закрывает то, что уже почти готово (прогрессивные таймауты и Cross-Channel Fingerprint сделаны), без новых внешних зависимостей.
3. Twitch-команды чатаОснова
!title / !game / !slow. Обработчик команд уже существует — нужен только новый OAuth scope и пара методов. Заметный эффект со стрима с первого дня.
4. EventSub + Stream Session MarkerОснова
Фундамент, от которого зависит половина всей аналитики в обоих банках ниже (Post-Stream Report, Timeline, Heatmap, Retention). Дольше и без видимого результата в первые дни — поэтому последний в порядке, хотя архитектурно самый важный.
Почему не OBS/TTS и не AI-функции сейчас: обе линии требуют новой инфраструктуры (push-канал вместо poll-WS, внешний LLM с вопросами приватности/стоимости) — вкладывать в них время раньше, чем закрыта основа, значит откладывать то, что уже приносит пользу стримеру каждый день модерации.
Часть 1

Разбор десяти предложенных направлений

Фаза, сложность, зависимости, польза стримеру, UX и рекомендация "сейчас / позже" — для каждой идеи отдельно. Сложность оценена по факту: что уже есть в коде против того, что придётся строить с нуля.

1. Twitch-команды из чата (!title, !game, !slow…)

Phase 4.5Сейчас
Сложность
Средняя
Зависимости
Новый OAuth scope (channel:manage:broadcast, moderator:manage:chat_settings) + новый Helix-клиент
Польза стримеру
Не выходя из игры — сменить title/game/slow-mode одной строкой в чате
UX
Обработчик команд уже существует (main.py, twitchio.ext.commands, префикс "!"), сейчас в нём две команды. Новые ложатся туда же тем же паттерном прав, что уже есть у !remember. Каждая команда обязана идти через Chat → Permission Check → Audit Log → Twitch API → Success/Fail — тот же принцип, что уже применяется к ручным банам, не в обход его.

2. Управление OBS (сцены, звуки, оверлеи)

Phase 4.5Позже
Сложность
Высокая
Зависимости
Новый push-канал (не подходит нынешний poll-WS), OBS WebSocket клиент — с нуля, нет ни строчки
Польза стримеру
Чат управляет сценой/звуком напрямую — сильный интерактив, но не про модерацию
UX
Существующий WS в панели — периодический снимок БД раз в 2 сек, не подходит для команды "сейчас переключи сцену". Нужен отдельный push-механизм (in-memory очередь подписчиков или отдельный WS-сервер) — реальная новая подсистема, не расширение старой. Ставить после того, как Twitch-команды (идея 1) обкатают паттерн прав/аудита на более простом случае.

3. TTS через OBS

Phase 4.5Позже
Сложность
Высокая
Зависимости
Напрямую зависит от идеи 2 (OBS-канал) + новый синтез речи (в проекте есть только STT, не TTS)
Польза стримеру
Донаты/сообщения озвучиваются вслух — классика для доната-based каналов

4. Mini Apps — система плагинов

Phase 4.5→7Позже
Сложность
Очень высокая
Зависимости
Требует, чтобы 3-4 реальных модуля (Polls, Timer, Soundboard…) сначала были написаны вручную — паттерн выводится из них, не придумывается заранее
Польза стримеру
Долгосрочно огромная — десятки модулей без раздувания кодовой базы
UX
Панель "включил галочку — появилась функция" — красивая идея, но архитектура плагинной системы, спроектированная до того, как написан хотя бы один плагин, почти всегда оказывается неверной. Правильный порядок: 3-4 модуля как обычный код → заметить общий паттерн (общая точка регистрации команд, общее хранилище настроек per-channel) → тогда формализовать в Apps-фреймворк.

Часть 2 · Банк 1

27 идей — первый проход

Сгруппировано по той же логике, что и разбор выше — что усиливает существующий модерационный core, что открывает новый Stream Operations, что превращает панель в полноценную аналитику.

Moderation — добить Phase 3 8 идей
Warning System
Формальное предупреждение как отдельное действие между OBSERVE и TIMEOUT — сейчас такой ступени нет вовсе.
Review Queue
Очередь пограничных вердиктов (confidence 0.4–0.7) на ручной просмотр — не пропадают в общем потоке Live.
Bulk Actions по фильтру
"Забанить всех с risk > 80 за последний час" одной кнопкой поверх уже существующего executor'а.
Ban Reason Templates
Готовые причины бана вместо ручного ввода каждый раз — быстрее и единообразнее в аудите.
Shadow Mode per pattern
Тестировать новый паттерн в SHADOW, не трогая общий режим канала — безопасная обкатка правил.
Appeal Flow
Забаненный зритель может подать апелляцию через форму — закрывает дыру в UNBAN-направлении.
Word Filter Severity Tiers
Не один словарь на всё — уровни (предупреждение / таймаут / бан) на категорию слов.
Moderator Score
% подтверждённых/отменённых действий модератора. Решено в аудите: видно только оператору/владельцу канала, не всей команде модераторов — аналитика, не публичный рейтинг.
Stream Operations — новое направление 6 идей
Stream Markers
!marker "босс появился" — метка на таймлайне, синхронизированная с VOD-таймкодом для монтажа клипов.
Auto-Clip on Spike
Всплеск сообщений/эмоутов → авто-триггер Twitch Clip API — ловит хайповые моменты без ручного нажатия.
Command Cooldowns per role
Разный кулдаун на команду для VIP/sub/обычного зрителя — стандарт для command-based ботов.
Scheduled Commands
"Каждые 20 минут напомнить про Discord" — не через внешний таймер-бот, а внутри самого CigilBot.
Stream Checklist
Чеклист "перед стримом" (title/game/оверлей/микрофон) прямо в панели, отмечается по ходу.
Sound Alerts на события
Не только по команде — авто-звук на конкретное событие (новый sub, рейд), тот же OBS-канал.
Analytics & Intelligence 8 идей
Incident Center
Отдельная страница: все атаки/рейды/всплески в одном месте, не разбросано по вкладкам.
Growth Trends
Не разовый снимок, а график "новых чаттеров/подписчиков" за месяцы — видно, растёт ли канал.
Detector Effectiveness Table
Какой детектор сколько ловит и какой у него FP-rate — уже есть частично, довести до полноценного экрана.
Peer Comparison (anon)
"Твой Chat Health выше среднего по каналам похожего размера" — обезличенно, across всех каналов оператора.
Retention Cohorts
Сколько новых зрителей с прошлого стрима вернулись — реальная метрика удержания аудитории.
Weekly Digest (не только daily)
Расширение уже существующего механизма digest — недельная сводка поверх ежедневной.
Export to CSV/PDF
Post-Stream Report и Analytics — экспорт для спонсорских отчётов и медиакитов.
Top Chatters Leaderboard
Публичная (или только для стримера) таблица самых активных — геймификация вовлечённости.
Community & Engagement 6 идей
Loyalty Points
Очки за активность в чате, обмен на что-то (шаутаут, приоритет в очереди) — база для мини-игр позже.
Custom Commands (no-code)Первый App
Стример сам создаёт !discord, !socials через панель, без кода. Решено в аудите: первый модуль Mini Apps System, когда до неё дойдём — ключевой для будущего SaaS-сценария.
Quote Database
!addquote / !quote — сохранённые смешные фразы чата, классика community-ботов.
Wheel of Fortune / Raffle
Розыгрыш прямо в чате — естественно совмещается с уже существующим Giveaway Mode (снижение чувствительности детекции).
Welcome Messages
Настраиваемое приветствие first-time чаттеру — тег first-msg уже читается детекторами, переиспользовать тот же сигнал.
Subscriber Milestones
Авто-алерт при round-number подписчике/зрителе — небольшой, но приятный штрих.
Часть 3 · Банк 2

30 идей — вторая сессия проектирования

От "CigilBot как операционная система канала". Часть идей пересекается или дополняет банк 1 — отмечено в описании. Ни одна не входит в основу (см. раздел выше) — но полезно видеть, куда расти дальше.

Stream Operations 3 идеи
Stream Notes
!note "баг с микрофоном" — заметки модератора собираются в таймлайн после стрима, не теряются в чате.
Stream Markers+
Расширение уже существующей идеи Stream Markers (банк 1) — типизированные метки (смешной момент/баг/клип/хайлайт) вместо одной общей.
Clip Candidates
Авто-детект пиков активности (рост сообщений/эмодзи/зрителей) как кандидатов на клип — переиспользует логику существующего burst-детектора, плюс Twitch Clip API.
Работа со зрителями 3 идеи
VIP Candidate System
Бот сам предлагает кандидатов на VIP по активности/стажу/чистой истории — среднего размера, не блокирует ничего.
Viewer Journey
Карточка "история игрока": первый визит/сообщение/саб/рейд/VIP. Каркас (first_seen, message_count) уже есть в mod_users — событийная часть требует EventSub.
Community Health
Расширенная версия Chat Health из разбора 10 идей — новые/вернувшиеся зрители, удержание, не только "здоровье" в моменте.
AI-функции 3 идеи
AI Chat Summary
Сводка тем каждые 30 минут — тот же вопрос приватности/стоимости, что у AI Stream Summary (разбор 10 идей, пункт 10).
AI Question Detector
Собирает вопросы зрителей, пропущенные стримером — узкая, дешёвая относительно других AI-идей: не нужен полный чат, только сообщения с "?".
AI Topic Detection
Топ тем за стрим — тот же блокер, что у AI Chat Summary, частично можно закрыть без LLM (частотный анализ ключевых слов).
Продвинутая модерация 3 идеи
Shadow Mode (per pattern)
То же, что Shadow Mode per pattern из банка 1 — движок уже по умолчанию в Mode.SHADOW, расширение до тестирования конкретного правила отдельно.
Appeal Center
То же, что Appeal Flow из банка 1 — аудит для него уже пишется в mod_actions, не хватает формы и экрана просмотра.
Moderator Score
% подтверждённых/отменённых действий модератора. Метрика простая (mod_actions уже хранит нужное), но как публичная оценка легко превращается в надзор за командой — обсудить культуру использования до того, как показывать цифру.
Аналитика 3 идеи
Stream Success Score
Единый рейтинг стрима из вовлечённости/активности/удержания — тот же принцип explainable, что и у Chat Health: раскрываемая карточка, не чёрный ящик.
Viewer Retention
Пришли/ушли за 5 минут/остались больше часа — уточнённая версия Retention Cohorts из банка 1.
Activity Heatmap
По часам, столбиками. Чистая визуализация уже копящегося mod_messages.created_at — самый дешёвый пункт всего банка 2.
OBS-интеграции 3 идеи
Voice Alerts (!say)
Дубль идеи TTS через OBS (разбор 10 идей, пункт 3) — тот же блокер: push-канал + синтез речи с нуля.
Scene Automation
Смена сцены по условию (низкий онлайн → убрать оверлей) — требует OBS-канала (разбор 10 идей, пункт 2) плюс отдельный движок правил.
Smart Countdown
!timer 10 в OBS — тривиален поверх готового OBS-канала, сам по себе не самостоятельная задача.
Интерактив 3 идеи
Giveaways 2.0
Розыгрыш с фильтрами (подписчики/стаж/чистая история) — совмещается с уже существующим Giveaway Mode.
Predictions+
Twitch Predictions с красивой статистикой в панели — среднего размера, не блокирует ничего другого.
Wheel of Names
Колесо участников через OBS — требует OBS-канала, сам по себе тривиален.
Далёкое будущее 3 идеи
Cross-Channel Reputation
Единый профиль пользователя across каналов оператора — Cross-Channel Bot Fingerprint уже переносит баны между каналами, это следующий шаг на той же инфраструктуре (fingerprints.db), не с нуля.
AI Moderator Assistant
Не модерирует сам — подсказывает модератору контекст ("4 жалобы за 15 минут"). Технически надстройка над уже существующими сигналами, но первая функция, которая говорит, а не показывает — требует зрелого Chat Health/Timeline под собой.
Stream Copilot
Советы стримеру в реальном времени ("активность падает, время для розыгрыша") — самый амбициозный пункт всего документа. Хороший горизонт, плохая точка входа: нет смысла строить без всего, что должно быть под ним.
Аудит 13.08.2026 — второй проход

Восемь вопросов, восемь ответов

Первый проход был неполным: три пункта помечались решёнными по одному лишь выбору состава основы, без вашего прямого ответа на сам вопрос. Здесь каждый вопрос задан заново — каждое решение ваше, не моя догадка за вас.

✓
Кто целевой пользователь?Решено: сейчас вы и ваша команда, но в будущем — продукт для чужих стримеров. Меняет требования к "необратимым" решениям уже сейчас (см. раздел SaaS-готовность ниже), но не приоритет фаз — Public Site остаётся Фазой 8.
✓
Stream Operations — новая Фаза 4.5, или часть Automation?Решено: отдельная 4.5. Twitch-команды входят в основу, OBS/TTS из неё вынесены в Фазу 7 — разные Twitch-права и разный риск-профиль не дают объединить их в одну фазу.
✓
OBS-интеграция — обязательное направление или экспериментальное крыло?Решено: отложена в банк (Фаза 7). Push-WS-инфраструктуру сейчас не проектируем — вернёмся, когда основа закрыта.
✓
Какие Mini App написать первыми, когда дойдём до Apps System?Решено: Custom Commands (no-code) — стример сам создаёт !discord/!socials через панель. Совпадает с решением про SaaS: это ключевой модуль для чужих стримеров, не только для себя.
✓
Chat Health — прозрачная формула или ML-модель?Решено: прозрачная формула, раскрываемая в карточку "из чего сложено" (активность/спам-rate/удержание). Совместимо с принципом explainable-прежде-AI, уже действующим в движке.
✓
AI-функции (Summary/Topic Detection/Question Detector) — где граница по данным зрителей?Решено: только агрегаты и ключевые слова во внешний LLM, без сырых сообщений зрителей. Дешевле и безопаснее по приватности, свод получится более поверхностным — принятый компромисс.
✓
Trust Score — менять модель или оставить как есть?Решено: оставить 4 категории (UNKNOWN/REGULAR/TRUSTED/PRIVILEGED). Уже работают в движке, policy и панели — переход на балл 0–100 был бы новой моделью данных без веской причины сейчас.
✓
Готовы ли вы к EventSub?Решено: да, входит в основу как первый пункт Фазы 4. Разблокирует Post-Stream Report, Timeline, Activity Heatmap, Viewer Retention и Viewer Journey разом.
Сверх исходных восьми: Moderator Score делаем, но видит его только оператор/владелец канала — команде модераторов видимость друг о друге даёт больше давления, чем пользы. Основу начинаем с Trusted Users-экрана: дешевле остальных трёх, а результат виден сразу.
Ограничение на выбор архитектуры

SaaS-готовность: только необратимое

Вы сегодня единственный оператор, в будущем — возможно, продукт для чужих стримеров. Multi-tenant UI и self-serve onboarding остаются в Фазе 8. Сейчас важно другое: не принять в основе решение, которое потом придётся переписывать с нуля.

Учитываем уже сейчас
Схема БД с расчётом на чужие каналы (уже так — broadcaster_id, не login), изоляция данных между каналами (уже так — mod.<id>.db), аудит-лог для любого действия (уже так — mod_actions).
Осознанно НЕ делаем сейчас
Self-serve онбординг, биллинг, multi-tenant UI с ролью "владелец продукта" поверх Operator, публичный лендинг. Всё это — Фаза 8, без изменений в приоритете.
